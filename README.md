# AI Backtesting Team — FOUNDATION_MODE build

Generated by the `ai-backtesting-team-builder` skill. **Mode: `FOUNDATION_MODE`** — this build ran with no target repository present, so it produced the portable 12-role core, a minimal generic skill corpus, and an intentionally empty rule set. See `.claude/backtesting-team/research/ARCHITECTURE_RESEARCH.md` for why.

## Install

Copy the `.claude/` directory into the root of your actual backtesting repository:

```bash
cp -r .claude /path/to/your/repo/
```

Claude Code discovers `.claude/agents/` and `.claude/skills/` automatically on the next session in that repository.

## The 12-role core

`bt-methods-researcher` → `bt-hypothesis-researcher` → `bt-data-integrity-specialist` / `bt-feature-label-methodologist` / `bt-execution-microstructure-specialist` → `bt-experiment-designer` → `bt-backtest-engineer` → `bt-statistical-reviewer` / `bt-risk-robustness-analyst` → `bt-experiment-integrity-reviewer` (independent final gate) → `bt-evidence-reporter`, all coordinated by `bt-team-orchestrator`.

Start a multi-stage run with, e.g.:

```text
Use the bt-team-orchestrator subagent to run a backtesting research cycle for <your strategy idea>
```

Or invoke any single role directly with `@agent-bt-<name>` or by name.

## What this build does not do

- It does not run a backtest, grant live-trading authority, or claim repository-specific optimality (per the builder's safety and stop conditions).
- It does not invent a market, venue, data vendor, or language — those are the first things `bt-methods-researcher`, `bt-data-integrity-specialist`, and `bt-execution-microstructure-specialist` will ask you to pin down once you point this team at a real repository.

## Next step — re-run for repository-specificity
